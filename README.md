# بوابة التواصل الإداري الداخلي

تطبيق **Node.js / Express** (قوالب EJS) محوَّل من 4 واجهات HTML ثابتة، وأصبح الآن **واجهة واحدة موحّدة ومترابطة** مع **حسابات مستخدمين**: عند إنشاء الحساب يختار المستخدم الحسابات التي يمكنه التواصل معها، ولا يرى أو يتصل بغيرها.

## التشغيل

```bash
npm install
cp .env.example .env      # ثم عدّل SESSION_SECRET
npm start                  # أو: npm run dev
```
افتح `http://localhost:3000` (لا تفتح ملفات `.ejs` مباشرة في المتصفح).

## المتغيرات (`.env`)

| المتغير | الوصف | الافتراضي |
|---|---|---|
| `PORT` | المنفذ | `3000` |
| `NODE_ENV` | `development` / `production` | `development` |
| `AGENCY_NAME` | اسم الجهة في الواجهات | `مصلحة الضرائب` |
| `SESSION_SECRET` | سر توقيع الجلسة (**إجباري في production**) | مفتاح تطوير مؤقت |
| `COOKIE_SECURE` | `true` عند التشغيل عبر HTTPS فقط | `false` |

## الصفحات

| المسار | الوصف | يتطلب دخولًا |
|---|---|---|
| `/login` | تسجيل الدخول | لا |
| `/register` | إنشاء حساب (زر «إنشاء حساب جديد» في **دليل الموظفين**؛ يعمل أيضًا لمن لا يملك حسابًا) | لا |
| `/calls` | **الصفحة الافتراضية بعد الدخول.** المكالمات الأخيرة (الحسابات والمطابخ المتاحة فقط) | نعم |
| `/directory` | دليل الموظفين (الحسابات المتاحة) + المطابخ المرتبطة تلقائيًا + زر إنشاء حساب | نعم |
| `/org` | **الهيكل الإداري الكامل، قابل للعرض والتعديل** (إضافة/تعديل/حذف وحدة، وتحديد مطبخ خاص بها) | نعم |
| `/call/active?contact=ID` | مكالمة صوتية أو تواصل مع مطبخ (معاينة) — **403** لأي حساب غير متاح | نعم |
| `/notifications` | الإشعارات | نعم |
| `/settings` | بيانات الحساب + تعديل الحسابات المتاحة للتواصل + عرض المطابخ المرتبطة | نعم |

لا توجد صفحة رئيسية منفصلة بعد الآن؛ `/` تُحوّل مباشرة إلى `/calls`. اسم صاحب الحساب وزر تسجيل الخروج يظهران في أعلى كل صفحة (الترويسة المشتركة)، وليس في صفحة مستقلة.

واجهة REST للقراءة (تتطلب دخولًا): `GET /api/calls` · `GET /api/contacts` · `GET /api/kitchens` · `GET /api/notifications` — كلها مفلترة حسب صلاحيات المستخدم.

## الهيكل الإداري والصلاحيات

- الهيكل في **`data/org.json`**، وأصبح الآن **قابلاً للتعديل من داخل التطبيق عبر صفحة `/org`** (لم يعد يحتاج تعديل الملف يدويًا، لكن ذلك ما زال ممكنًا). أعدت بناءه ليطابق **مخطط الهيكل التنظيمي الذي أرسلته كصورة**: فرعان تحت رئيس المصلحة — فرع «مكتب شؤون رئيس المصلحة» وفرع «نائب رئيس المصلحة» — كل منهما يضم مكاتبه وإداراته وإداراته الضريبية بالمناطق.
- **قاعدة مهمة أوضحتها**: مدير أي **إدارة** (🏢) يتواصل مع **المرتبة الأعلى منه بدرجة واحدة فقط**، وهي دائمًا **رئيس المصلحة ونائبه**، بغض النظر عن فرع المكتب الذي تتبعه إدارته في المخطط. كما أن كل مديري الإدارات (عامة أو فنية أو ضريبية بالمناطق) **نظراء لبعضهم** (نفس المستوى)، حتى لو كانوا في فرعين مختلفين من الشكل. هذه القاعدة مطبّقة في `orgService.relatives()` ولا تعتمد على عمق الشجرة.
- بالنسبة لبقية الوحدات (مكاتب، أقسام، نائب الرئيس نفسه): العلاقة تبقى حسب الشجرة الفعلية — المدير = الوحدة الأصل مباشرة، ونفس المستوى = الوحدات الشقيقة تحت نفس الأصل.
- عند التسجيل يختار المستخدم **موقعه في الهيكل** (مستقل عن مسماه الوظيفي)، فتظهر له تلقائيًا:
  1. **المرتبة الأعلى بدرجة واحدة** (مديره المباشر، أو رئيس المصلحة ونائبه إن كان مدير إدارة).
  2. **نفس المستوى الإداري** (زملاؤه ونظراؤه).
  3. **من يندرج أسفل وحدته**.
- **الفرض من الخادم**: الدليل والمكالمات وواجهة API وصفحة المكالمة تعرض/تسمح فقط بما اختاره المستخدم **وبما يسمح به الهيكل حاليًا**؛ تعديل الرابط أو إرسال معرّف غير مسموح لا يتجاوزها.
- **صفحة `/org`**: عرض شجري كامل، وإضافة وحدة تابعة (مكتب/إدارة/قسم) مع مطبخ خاص اختياري، وتعديل الاسم أو المطبخ، وحذف وحدة — **يُمنع حذف وحدة بها حسابات** (بحث تلقائي في كل الحسابات عند أو أسفل الوحدة) حتى تُنقل الحسابات أولًا. الحذف والتعديل مفتوحان لأي مستخدم مسجّل دخول في هذه المعاينة.

## المطابخ (جهات تواصل تلقائية)

- **`data/kitchens.json`**: مطبخان مشتركان («مطبخ 1»، «مطبخ 2») يخدمان القيادة العليا وكل الإدارات العامة والفنية، بالإضافة إلى **مطبخ مستقل لكل إدارة ضرائب بالمناطق (27 مطبخًا)** باسمها — كما ورد في التوزيع الذي أرسلته.
- الربط بحسب موقع المستخدم في الهيكل، لا يدويًا بالكامل:
  - **الإدارات الضريبية بالمناطق**: مطبخ واحد ثابت (لا اختيار).
  - **القيادة العليا وكل الإدارات العامة/الفنية**: تقع ضمن نطاق **مطبخين مشتركين (مطبخ 1 / مطبخ 2)**، ويختار المستخدم **أحدهما عند التسجيل (إلزامي)**، ويمكنه تغيير اختياره لاحقًا من **الإعدادات**.
- تظهر المطابخ في «دليل الموظفين» (قسم منفصل، بأيقونة طاهٍ مميزة) وفي نموذج التسجيل والإعدادات (اختيار أو عرض حسب الحالة).

## الأمان

- كلمات المرور مُجزّأة بـ `scrypt` مع salt لكل مستخدم (لا تُخزَّن نصًا).
- جلسة موقّعة (`cookie-session`): `httpOnly` + `sameSite=lax`.
- رمز CSRF لكل نموذج POST، وحد لمحاولات الدخول/التسجيل، ومنع التحويل الخارجي بعد الدخول.
- `helmet` مع CSP مقيّدة بمصادر التصميم فقط.

## البحث والتصفية عند اختيار الحسابات

قوائم «المرتبة الأعلى / نفس المستوى / أسفل وحدتك» في التسجيل والإعدادات مزوّدة بأزرار تصفية حسب نوع العلاقة، وقائمة منسدلة للتصفية حسب الوحدة الفرعية المحددة، إضافة إلى مربع بحث نصي — مصمّمة لتبقى قابلة للاستخدام حتى مع آلاف الحسابات (لا تعتمد فقط على البحث النصي).

## الحسابات والصورة الموحدة

تم إنشاء حساب واحد لكل وحدة في الهيكل الإداري كاملًا (75 حسابًا: من رئيس المصلحة إلى كل قسم)، بصورة رمزية واحدة موحّدة لجميع الحسابات، وبلا حقل «مسمى وظيفي» (أُلغي بالكامل من التسجيل والعرض في كل الصفحات؛ اسم الحساب نفسه يعكس الموقع، مثل «مدير إدارة المعلوماتية»). عدّل الأسماء أو الصورة في `data/accounts.json` متى شئت.

## ملاحظات مهمة

1. **التخزين ملفات JSON** (`data/users.json`, `data/org.json`) — مناسب للمعاينة/التطوير. للإنتاج الفعلي استبدل `dataService` بقاعدة بيانات، ويُفضّل حينها تقييد تعديل `/org` بصلاحية مسؤول بدل إتاحته لكل مستخدم.
2. **افتراضات في تفسير المخطط** (قابلة للتعديل من `/org` مباشرة): قسم «شؤون إدارية» ثبّتّه تحت نائب الرئيس مباشرة (وليس تحت مكتب بعينه)؛ توزيع الإدارات الضريبية الـ27 بين الفرعين (11 تحت فرع مكتب شؤون الرئيس، 16 تحت فرع نائب الرئيس) هو أقرب قراءة ممكنة للصورة المرفقة وقد لا يطابق التوزيع الفعلي حرفيًا — لاحظ أن توزيعها بين الفرعين **لا يؤثر على الصلاحيات** أصلًا بسبب قاعدة «مديرو الإدارات نظراء لبعضهم» أعلاه، فهو تنظيمي بصري فقط ويمكن تصحيحه من `/org` إن أردت.
3. **مواقع الموظفين الثمانية الأساسيين** بقيت كما حدّدتها سابقًا (عدّلها في `data/accounts.json` عبر `unitId` إن احتجت لتغييرها بعد إعادة بناء الشجرة).
4. **حذف صفحة الرئيسية**: أي رابط أو استيراد قديم لها أُزيل؛ الصفحة الافتراضية بعد الدخول أصبحت `/calls`.
5. التسجيل مفتوح لأي زائر يصل للموقع. للاستخدام الفعلي يُنصح بتقييده (دعوة/موافقة مسؤول)، والأمر نفسه ينطبق الآن على تعديل `/org`.
6. المكالمات والتواصل مع المطابخ **معاينة فقط**؛ لا تُجرى مكالمات فعلية.
7. حُذفت سكربتات `/_sdk/*` الخاصة بأداة التصدير الأصلية، وعُطّل `upgrade-insecure-requests` في CSP لأنه كان يُفقد الصفحة تنسيقها في بعض المتصفحات على `http://localhost`.
