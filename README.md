# بوابة التواصل الإداري الداخلي

تطبيق **Node.js / Express** (قوالب EJS) محوَّل من 4 واجهات HTML ثابتة، وأصبح الآن **واجهة واحدة موحّدة ومترابطة** مع **حسابات مستخدمين**: عند إنشاء الحساب يختار المستخدم الحسابات التي يمكنه التواصل معها، ولا يرى أو يتصل بغيرها.

## التشغيل

```bash
npm install
cp .env.example .env      # ثم عدّل SESSION_SECRET
npm start                  # أو: npm run dev
```
افتح `http://localhost:3000` (لا تفتح ملفات `.ejs` مباشرة في المتصفح).

## المتغيرات (`.env`)

| المتغير | الوصف | الافتراضي |
|---|---|---|
| `PORT` | المنفذ | `3000` |
| `NODE_ENV` | `development` / `production` | `development` |
| `AGENCY_NAME` | اسم الجهة في الواجهات | `مصلحة الضرائب` |
| `SESSION_SECRET` | سر توقيع الجلسة (**إجباري في production**) | مفتاح تطوير مؤقت |
| `COOKIE_SECURE` | `true` عند التشغيل عبر HTTPS فقط | `false` |

## الصفحات

| المسار | الوصف | يتطلب دخولًا |
|---|---|---|
| `/login` · `/register` | تسجيل الدخول · إنشاء حساب واختيار الحسابات المسموح بها | لا |
| `/` | الرئيسية (ملخص + المتصلون الآن) | نعم |
| `/directory` | دليل الموظفين (الحسابات المسموح بها فقط) | نعم |
| `/calls` | المكالمات الأخيرة (مع الحسابات المسموح بها فقط) | نعم |
| `/call/active?contact=ID` | مكالمة صوتية (معاينة) — **403** لأي حساب غير مسموح | نعم |
| `/notifications` | الإشعارات | نعم |
| `/settings` | بيانات الحساب والحسابات المتاحة | نعم |

واجهة REST للقراءة (تتطلب دخولًا): `GET /api/calls` · `GET /api/contacts` · `GET /api/notifications` — كلها مفلترة حسب صلاحيات المستخدم.

## كيف تعمل الصلاحيات

- عند التسجيل يُخزَّن `allowedContacts` (قائمة معرّفات) في `data/users.json`.
- **الفرض من الخادم**: الدليل والمكالمات وواجهة API وصفحة المكالمة كلها تمر عبر `accountService.getContactsFor()` / `canContact()`؛ تعديل الرابط يدويًا لا يتجاوزها.
- الصلاحية أحادية الاتجاه: اختيارك للحساب لا يمنحه صلاحية التواصل معك.
- الحسابات المتاحة للاختيار = الموظفون الثمانية الأساسيون + أي حساب مسجَّل لاحقًا.

## الأمان

- كلمات المرور مُجزّأة بـ `scrypt` مع salt لكل مستخدم (لا تُخزَّن نصًا).
- جلسة موقّعة (`cookie-session`): `httpOnly` + `sameSite=lax`.
- رمز CSRF لكل نموذج POST، وحد لمحاولات الدخول/التسجيل، ومنع التحويل الخارجي بعد الدخول.
- `helmet` مع CSP مقيّدة بمصادر التصميم فقط.

## البنية

```
server.js
src/{config,routes,controllers,services,middleware}
views/{partials,pages}      # layout-start/end + sidebar موحّدة لكل الصفحات
public/{css,js}
data/                       # accounts.json, users.json, calls.json, notifications.json
```

## ملاحظات مهمة

1. **التخزين ملفات JSON** (`data/users.json`) — مناسب للمعاينة/التطوير. للإنتاج الفعلي استبدل `dataService` بقاعدة بيانات.
2. **توحيد البيانات**: ملفات الواجهات الأصلية كانت تصف الشخص نفسه بمعلومات مختلفة (مثلًا «خالد عمر بوحليقة»: محلل نظم/التحول الرقمي في المكالمات، وأخصائي موارد بشرية في الدليل؛ و«سارة النعاس» بالمثل). اعتُمدت بيانات **الدليل** كمرجع موحّد. أما «مريم العبيدي» و«يوسف المصراتي» (يظهران في المكالمات فقط) فأُضيفا كحسابين بدون قسم/مكتب/منطقة (تظهر «—»).
3. **إزالة «عرض البيانات حسب الصلاحية»** (موظف/مشرف/مدير) من الدليل: كانت معاينة وهمية، وحلّت محلها الصلاحيات الحقيقية أعلاه.
4. **الرئيسية والإعدادات** كانتا تبويبين بلا محتوى في الأصل؛ أصبحتا صفحتين فعليتين. «الإدارات» تفتح فلاتر الدليل.
5. المكالمات والرسائل **معاينة فقط** كما في الأصل؛ سجل المكالمات بيانات تجريبية تُعرض للحسابات المسموح بها.
6. سكربتات `/_sdk/*` الخاصة بأداة التصدير الأصلية حُذفت (روابط مكسورة خارج بيئتها).
7. تم تعطيل `upgrade-insecure-requests` في CSP: كان يسبب صفحة بلا تنسيق في بعض المتصفحات (مثل Safari) عند التشغيل على `http://localhost`.
